能力 · CLI-agent 后端

带上你的 agent，而不是你的密钥。

aic 可以委托给你的本地 AI 编码 agent —— Claude Code、Codex、Pi 或 OpenCode —— 在 headless 模式下运行。无需 API 密钥，无需默认模型，无需中间人：你的 agent 读取 diff 并写出提交，复用它自己的模型和授权。

→ 然后运行 aic setup → 选择 agent 后端

工作原理

同一套循环，换一个后端。aic 不再调用 LLM API，而是以 print 模式 shell 调用你的 agent，把 diff 传过去，让它做最擅长的事 —— 推理这次改动并写出提交信息。

  1. 选择 agent 后端 运行 aic setup，选一个 CLI agent 而不是 API 供应商。aic 会记住它。
  2. 委托，而非调用 当你运行 aic 时，它会 shell 调用你的 agent —— 例如 claude -p —— 把 diff 和 prompt 传过去。推理由 agent 完成。
  3. 同样的提交输出 你的 agent 返回提交信息。aic 把它写进你的 git 历史 —— 批处理、约定式、彩色，一如既往。

四个 agent，一个后端

开箱即用四个预设。每个复用各自的授权 —— 只要 agent 已经装好，就无需额外配置。

  • Claude Code 通过 thinking_delta 实时流式输出推理过程。你看 agent 思考，然后提交。
  • Codex 在只读沙盒中静默运行，完成后返回提交信息。
  • Pi 实时流式输出推理过程，和 Claude Code 一样。
  • OpenCode 静默运行，复用你已有的供应商密钥（例如 Cursor OAuth）。

切换你的后端 —— 不要两个都跑

backend_kind 是一个判别字段：每次运行只有一个后端生效。API 路径（provider · key · model）和 agent 路径（你的本地 CLI）是二选一，而不是叠加。

再运行一次 aic setup 即可切换。aic 只保存一份配置；你最后一次选的后端就是它使用的那个。

或者任意自定义 agent

在这四个预设之外，你可以把任意 CLI 命令配置为你的 agent。只要它从 stdin 接收 prompt 并向 stdout 输出，aic 就能驱动它。

为什么这么快

没有 API 跳转，没有新增授权。你的 agent 早已经把模型加载好并完成了认证 —— aic 只是把 diff 传过去，再把提交信息读回来。

速度来自跳过了配置步骤，而不是来自更快的模型。你复用的是 agent 的会话和凭据。

简而言之

aic + 你的编码 agent：agent 负责推理，aic 负责提交。无需 API 密钥，无需中间人，无需挑选模型 —— 输出的依然是 aic 一贯产出的那种批处理、约定式、彩色的历史。

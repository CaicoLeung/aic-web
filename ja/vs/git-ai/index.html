aic vs git-ai

git-ai はローカルファーストの Git アシスタント — コミットメッセージ、PR 説明、デフォルトでゼロ設定の Ollama。まだ初期段階（v0.1.3）で2026年初頭から静かですが、PR 説明という角度は本物です。このページは公平に比較します。aic が勝つのはアトミックな履歴が重要な場面：hunk レベルのバッチングと AI コンフリクト解決、依存のない Rust バイナリで。

2つのヘルパー、異なる範囲。 git-ai は git をアシスタントで拡張します（コミット + PR 説明、ローカルファースト）。aic は1つのことを深く：クリーンでアトミックな conventional コミット履歴 — そしてマージコンフリクトの解決。

aic をインストール →

aic がリードする点

  • 未ステージの作業を複数コミットに自動バッチング aic の看板機能。git-ai はステージした内容に1メッセージを書くだけ。
  • 単一ファイルを複数コミットに分割（per-hunk） aic は hunk レベルで diff を読みます；git-ai（ラウンドアップの全ツール同様）はファイルを原子単位とします。
  • マージコンフリクトの解決 git-ai にはコンフリクト対応がありません — マージは手作業のまま。
  • ランタイムと依存 aic は単一の静的バイナリ；git-ai は Node と scoped npm パッケージで動作。
  • セットアップ aic は プロバイダー → キー → モデル を案内；git-ai は CLI で設定。
  • プロバイダー網羅 aic は妥当なデフォルトモデルを持つ一級プロバイダーがより多い。
  • プロジェクトの活動状況 aic は毎週リリース；git-ai は約6ヶ月休眠。
  • 複数のメッセージ候補 トレードオフ どちらも N 個から選ぶメニューはありません — 1メッセージのみ。

git-ai がまだ勝つ点

git-ai はラウンドアップで唯一 PR 説明を作成し、無料のローカルモデルをデフォルトにします。どちらかがアトミックな履歴より重要なら、公平な選択です：

  • PR 説明 git-ai は PR タイトルと説明を作成；aic はコミットと解決に集中。
  • ローカルファーストのデフォルト git-ai はすぐにオフラインで動作；aic はプロバイダーキーが必要だが Ollama もサポート。
  • コミットメッセージ形式 git-ai は gitmoji 形式を提供；aic は設計上 conventional のみ。

よくある質問

aic は git-ai の良い代替になりますか？

未ステージの作業を論理コミットに分割し、マージコンフリクトを解決したいなら、はい。PR 説明と無料ローカルデフォルトが欲しいなら git-ai は依然として興味深いです。

aic は PR 説明を作成しますか？

いいえ — aic はコミットとコンフリクト解決に集中します。PR 説明は git-ai のラウンドアップでの強みです。

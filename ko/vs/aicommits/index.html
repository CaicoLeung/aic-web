aic vs aicommits

aicommits 는 AI 커밋 메시지 도구에서 자리 잡은 기본 선택 — 설치 기반, 생태계, 선발주자로서의 추진력. 이 페이지는 그렇지 않은 척하려는 게 아닙니다. aic가 언제 더 나은 선택인지 — 그리고 언제 그냥 aicommits에 머물러야 하는지 정확히 알려줍니다.

좁은 세상이네요. aicommits 자체 README도 이름이 너무 길면 aic로 별칭하길 권합니다. 우리는 aic를 독자적인 도구로 출시했습니다 — 그리고 hunk 단위로 미스테이지 작업을 논리적인 커밋으로 쪼개, 한 파일도 여러 개가 될 수 있습니다.

aic가 앞서는 부분

  • 미스테이지 작업을 여러 커밋으로 자동 배치 aic의 대표 기능. aicommits의 `--generate N`은 한 커밋에 대해 N개의 후보 메시지를 만드는 것이지, N개의 커밋이 아닙니다.
  • 한 파일을 여러 커밋으로 분할(hunk별) aic v0.3.5에 탑재. aicommits(및 roundup의 모든 도구)는 기껏해야 파일 경계에서 분할; aic는 hunk 단위로 diff를 읽어, 세 가지 관심사를 담은 한 파일이 세 개의 집중된 커밋이 됩니다.
  • 병합 충돌 해결 aic의 두 번째 대표 워크플로(`v0.3.0`). aicommits엔 충돌 이야기가 없습니다 — 손으로 병합한 뒤에야 메시지를 씁니다.
  • 마지막 실행 되돌리기 aic v0.5.8 탑재. 실수 하나에 대화형 `git reset` 대신 명령 한 번: 실행의 커밋이 제거되고 모든 변경이 미스테이지로 돌아가며, 히스토리가 진행됐으면 거부합니다. aicommits에는 되돌리기가 없습니다 — 잘못 쓰인 AI 메시지는 직접 고쳐야 합니다.
  • 전송 전 시크릿 검열 aic v0.5.8 탑재, `aic`와 `aic resolve` 모두에 적용. diff에 클라우드 키·토큰·개인 키가 있으면 기계 밖으로 나가기 전에 실행이 멈춥니다 — aic는 파일과 패턴을 지적합니다. `--no-redact`로 끌 수 있습니다. aicommits는 diff를 그대로 모델에 보냅니다.
  • 일급 Anthropic · Gemini · DeepSeek aicommits는 간접적으로만 도달; aic는 일급으로 출시하고 합리적인 기본 모델을 붙입니다.
  • 런타임과 의존성 aic는 하나의 정적 바이너리 — `node_modules`도, 전이 의존성 트리도 없고, Node 버전을 바꿔도 글로벌 설치가 망가지지 않습니다. (Rust의 더 빠른 콜드스타트도 도움 되지만, 어찌 됐든 LLM 호출이 지배적입니다.) aicommits가 마찰 없인 건 Node.js가 이미 경로에 있을 때뿐입니다.
  • 프로바이더 도달 범위 둘 다 OpenRouter로 모든 모델에 도달하지만, aic는 더 많은 일급 프로바이더를 출시 — xAI, Together, Perplexity, Mistral 포함 — 에 더해 LM Studio, vLLM, 게이트웨이용 OpenAI 호환 탈출구도.

aicommits가 여전히 이기는 부분

aic가 인기 도구를 모든 면에서 이긴 척하지 않겠습니다. 이기지 못합니다. 이것들이 자동 배치보다 더 중요하다면, aicommits가 맞는 선택입니다:

  • 커밋 메시지 형식 aic는 설계상 컨벤셔널만 지원합니다. aicommits는 일반 비구조 모드를 포함해 고를 수 있게 합니다.
  • Git 훅 통합 aicommits는 훅으로 일상적인 `git commit` 흐름에 연결; aic는 명시적으로 실행합니다.
  • 여러 메시지 후보 aicommits는 커밋 전에 몇 가지 메시지를 골라볼 수 있습니다.
  • 프롬프트와 로케일 제어 aicommits가 더 풍부한 조절 옵션을 제공합니다. aic는 `AIC_SYSTEM_PROMPT` 재정의를 지원하지만 사용할 수 있는 옵션은 더 적습니다.
  • 인기와 생태계 aicommits는 더 큰 커뮤니티를 가진 알려진 양입니다. 추진력이 가장 중요하다면, 계속 쓰세요.

자주 묻는 질문

aic는 aicommits의 좋은 대안인가요?

스테이징하지 않은 작업을 논리 커밋으로 나누고(단일 파일 안에서도) 머지 충돌을 AI로 해결하고 싶다면, 그렇습니다. git 훅, gitmoji 커밋, 여러 후보에 의존한다면 aicommits가 적합합니다.

aic도 aicommits처럼 Node.js가 필요한가요?

아니요. aic는 단일 Rust 바이너리입니다 — node_modules도 npm 전역 설치도 Node 버전 문제도 없습니다.

한 줄 요약

미스테이지 작업이 쌓이고 깔끔하고 논리적인 커밋으로 쪼개고 싶거나, Node.js 의존 없이 Claude, Gemini, DeepSeek을 일급 프로바이더로 쓰고 싶다면 aic로 전환하세요. git commit 훅, gitmoji 커밋, 고를 수 있는 여러 후보, 또는 그저 인기 있는 선택의 편안함을 원한다면, aicommits도 여전히 훌륭한 도구입니다.
